### Close the Second Production Deployment Delta Review
- **Room rotation bypassed every TURN quota.** Room ids are client-chosen and creating a room is free, so an attacker could make a fresh room, join it, mint a fresh admission token, and get a fresh room *and* seat allowance on every request — the per-room limiter bounded what one room cost and nothing more. Added an independent ceiling in its own singleton Durable Object (`TURN_QUOTA_DO`, one instance for the whole deployment) that counts what an attacker cannot re-key: 30 burst per client address, 5 burst shared by callers with no trusted address, and a deployment-wide 600 burst / 1 per second that is the actual protection for the TURN bill. Tracked addresses are capped at 4 096, and an unknown client is refused rather than admitted once that cap is reached, so address rotation cannot exhaust the object's memory either.
- The address comes **only** from `CF-Connecting-IP`, which Cloudflare's edge sets and overwrites on every forwarded request. `X-Forwarded-For`, `X-Real-IP`, `True-Client-IP`, and `Forwarded` are client-controlled and are never read — honouring one would hand an attacker a fresh bucket per request for the price of a header. IPv6 is bucketed by /64, since a single customer is routinely delegated a whole prefix and rotating inside it would otherwise be free.
- The ceiling is consulted **before** the room and charged for the *attempt*, not the success, so a flood of forged tokens is metered and cannot spin up a Durable Object per fabricated room id. It fails **closed**: a limiter that opens when knocked over is not a limiter, and a missing TURN credential is already non-fatal (the launcher falls back to direct/STUN ICE with a visible warning). Room and seat authorization are unchanged and still run afterwards. Documented the Cloudflare rate-limiting and WAF rules that belong in front of the Worker, which are zone configuration rather than repository state.
- **Arbitrary Durable Object ids persisted room keys.** The room object's constructor created and stored a signing key unconditionally, so `idFromName()` on any string — including a room id peeked out of a forged token — left a durable storage record behind: an unauthenticated write amplification. Keys are now only *loaded* on construction and only *created* once a join has been accepted, and the room's whole storage is cleared when the last member leaves. Extracted the lifecycle into `admission-key-store.ts` so the *timing* of the write is unit tested, and added `room-do.test.ts` asserting that constructing an object and answering a turn-grant request both write nothing at all.
- **`retry.ts` used TypeScript parameter properties.** Node runs these operator scripts directly by stripping types, which erases annotations without emitting code, so `PropagationTimeoutError`'s fields would silently never have been assigned in production even though Vitest's transform made the tests pass. Replaced them with explicit field declarations and verified by running the real production smoke command.
- **A departed peer could be recreated by its own buffered signal.** Signals wait for this join's TURN fetch; departures did not. So an offer buffered before a peer left was dequeued afterwards and built a connection to somebody no longer in the room. Departures are now recorded the instant they are observed, buffered signals from a departed slot are dropped, and a roster snapshot held back for the fetch has the departed slot removed from it. Recording the departure is deliberately preferred to queueing the teardown: queueing would still build the connection and answer the offer first, and a teardown dequeued after the seat had been refilled would have torn down the *new* occupant. A slot the roster lists again is un-marked, so a replacement player still connects normally.
- **The retry budget only counted sleeping.** A half-open connection to a brand-new DNS record hangs rather than erroring, so one such request could stall a deploy indefinitely while the budget showed as untouched. Time spent inside a request now draws the shared budget down, and every request carries an abort deadline — 15s, clamped to whatever is left of the budget when it is a retry. A run is bounded by `requests x 15s + retry budget`. A first probe keeps its full deadline even after the budget is gone, so a healthy origin is never aborted because an unrelated one was unreachable.
- **`deploy-web.yml` still interpolated `--require-turn`,** a flag removed when the TURN check became an authorization-refusal check, so every credentialed production smoke run would have died on an unknown argument. Removed the input and the interpolation, and added a drift test that reads the accepted flags out of the CLI parser and checks every `npm run smoke` invocation in the workflow against them.
- **`--strict` was described as guarding concurrent deploys.** It does not: it refuses an upload when the live Worker's *settings* have drifted from `wrangler.toml` (a dashboard edit), and Wrangler has no compare-and-swap on the deployed script version at all — `wrangler deploy` is last-write-wins and the loser gets no error. ### Close the Production Deployment Integration Review Findings
- **TURN credentials were publicly mintable.** `GET /turn-credentials` was reachable by anyone who could reach the Worker; only CORS stood in front of it, and CORS is a browser-side *read* restriction that curl, a script, or any server simply ignores — `Origin` is trivially forged outside a browser. Replaced it with a room-scoped capability: each room's Durable Object generates its own 32-byte HMAC key in its own storage, mints a short-lived (5 min) `{roomId, slot, admissionId, exp}` admission token when a player joins, and returns it in the `welcome`. A token minted for one room can never validate against another, and there is no operator-managed shared secret to leak or rotate.
- Authorization happens *inside* the Durable Object in the order signature → is this seat still held by this `admissionId`? → rate limit. `admissionId` is a fresh nonce recorded on the seat, so leaving, disconnecting, or being replaced revokes the token instantly with no revocation list. The Durable Object is the single authority for its room, so its dual token bucket (5/min per seat, 20/15s per room) cannot be bypassed by spreading requests across Worker isolates or colos — a Worker-local limiter could have been. Denials return 401, or 429 with `Retry-After`; a Durable Object transport failure is distinguished from a decision and returns 503.
- Reordered the launcher to **join first, then fetch TURN**, since credentials now require a token the room issues. No `RTCPeerConnection` is constructed until the fetch settles, so no peer is ever pinned to placeholder ICE servers; roster and signal messages arriving during the fetch are buffered and replayed in arrival order, which also closes a pre-existing hazard where `addIceCandidate` could run before `setRemoteDescription`.
- Rewrote the smoke suite's TURN check to assert credentials are *refused*: it presents an allowed `Origin` with no token, and with a forged token, and requires 401 both times. The suite now holds and issues no credential at all, so it is safe to run against production on every deploy.
- **Post-deploy probes had no propagation tolerance.** A freshly attached custom domain is not resolvable the instant it uploads, so a correct deployment could be reported as broken. Added bounded exponential backoff (6 attempts, 2s→20s, 120s total budget) that retries only propagation-shaped failures — transport errors and `408/425/429/5xx/520-527`. Retrying happens inside the fetch, never around a check's assertions, so a wrong header, a stale release id, or a 404 still fails on the *first* attempt. The budget is shared across origins, an origin that answered once is never waited on again, and an origin that exhausts its attempts fails every later check immediately, so a total outage terminates in ~2 minutes rather than ~20. Giving up names the origin, attempt count, elapsed time, and the underlying failure. `deploy-worker.sh`'s `/readyz` poll got the same bounded treatment.
- **`wrangler.toml` claimed `keep_vars = false` prevented publishing over someone else's version.** It does not — it only makes that file the single source of truth for non-secret vars (dashboard-added vars are intentionally removed on deploy; secrets are a separate store and are never deleted). Corrected the comment and added the flag that actually does the job: `wrangler deploy --strict`, which refuses an upload when the live Worker carries changes this deploy did not produce. Added a script-drift test asserting the real upload is strict while the preceding `--dry-run` deliberately is not.

### Add the Authorized Streaming Asset Pipeline for the Browser Launcher
- Replaced the launcher's buffer-everything-then-cache downloader, which read each whole response with `arrayBuffer()` into the JS heap before writing it to the Cache Storage API — unusable for multi-gigabyte BIG archives and impossible to resume.
- Raised the shared engine manifest to schema v2 with a strict role vocabulary (`engine-js`, `engine-wasm`, `engine-data`, `big-base`, `big-expansion`, `script`, `font`), per-asset mount metadata (target, load order, streaming flag), and an `assetsRevision`. Validation now enforces role cardinality, unique mount targets and orders, expansions ordered strictly after base archives, traversal-free paths, absolute mount targets, strong-only ETags, and per-asset and total size ceilings.
- Added a pure-TypeScript incremental SHA-256 because `crypto.subtle.digest` is one-shot: streaming verification of a gigabyte archive is impossible without an incremental hasher. Its output is checked byte-for-byte against WebCrypto in tests.
- Downloads now stream the response body directly into an OPFS temp file in bounded chunks, hashing as they go, and verify the exact byte count and digest before the file becomes visible. Oversized responses are aborted mid-stream instead of being read to completion.
- Promotion from temp to final is atomic: `FileSystemFileHandle.move()` where the browser supports it, otherwise a chunked copy followed by a size check that detects a torn copy.
- Interrupted downloads resume with `Range` + `If-Range`, but only after a sidecar record matching digest, size, URL, ETag, engine version, and assets revision is confirmed and the bytes already on disk are re-hashed. A `200`, a `416`, or a `Content-Range` that disagrees with the request restarts cleanly from zero. A completed temp file left behind by a crash is promoted with no network request at all.
- Made cache keys immutable: final files are content-addressed by digest under a `${engineVersion}-r${assetsRevision}` root, so republishing prunes the previous revision instead of mixing revisions, and unreferenced files inside the live root are collected.
- Separated the failure policies deliberately: integrity and size failures delete the partial file and its resume record, while cancellation, quota exhaustion, and dropped connections keep both so the next boot resumes.
- Storage pressure is now surfaced as a typed quota error carrying required and available bytes, checked before the first byte is fetched rather than discovered halfway through.
- Added a bounded-memory virtual file system so the engine reads BIG archives by range through a small LRU chunk cache; whole-file reads are refused for streaming roles and oversized files.
- Added an in-memory storage backend with identical semantics for browsers without OPFS, which also makes every path — resume, atomic promotion, garbage collection — testable without a real filesystem.
- Added an operator-side manifest builder that streams a locally staged, licensed install to produce a manifest. No retail asset, digest list, or manifest is committed to this repository.
- Covered the pipeline with unit tests over mocked fetch, streams, and filesystem: digest mismatch, short and oversized responses, resume and range validation, ETag drift, atomicity and crash recovery, on-disk corruption, cancellation, quota failure, concurrency bounds, and the non-OPFS fallback.
- Documented the delivery contract an authorized origin must meet (byte ranges, strong ETags, immutable caching, CORS exposure of `ETag`/`Content-Range`) in `docs/HOWTO/WEB_ASSET_PIPELINE.md` and the `web/` README.

### Fix Multi-Monitor Window Placement and HiDPI Window Sizing
- Fixed the game opening on a secondary monitor at an oversized width on multi-monitor macOS setups.
- Root cause was a unit mismatch: `buildFilteredResolutions()` clamps the resolution list against `SDL3_GetNativeDisplaySize()`, which returns `mode->w * pixel_density` (physical pixels), but `SDL3_ApplyWindowModeForRenderConfig()` passed those values straight to `SDL_SetWindowSize()`, which expects logical points. On a 2x Retina display a 3840x2160 render resolution produced a 7680-physical-pixel-wide window — twice the width of the whole desktop.
- The oversized window then spanned both displays, and because SDL resolves a window's display by its center point, `SDL_GetDisplayForWindow()` reported the adjacent monitor and the window migrated there.
- `SDL3_ApplyWindowModeForRenderConfig()` now derives the pixel-to-point ratio from the window itself (`SDL_GetWindowSizeInPixels` / `SDL_GetWindowSize`) rather than the display's `pixel_density`. The drawable is only scaled when the window carries `SDL_WINDOW_HIGH_PIXEL_DENSITY`, which is set on macOS only, so the ratio collapses to 1.0 on other platforms and non-HiDPI behavior is unchanged.
- `SDL_CreateWindow()` takes no position argument and resolves to `SDL_WINDOWPOS_UNDEFINED`, which SDL maps to display index 0 of its own enumeration order rather than the OS primary display. `SDL3Main.cpp` now pins the initial placement to `SDL_GetPrimaryDisplay()` while the window is still hidden, so there is no visible jump and fullscreen no longer inherits the wrong display.
- Added `SDL3_CenterWindowOnCurrentDisplay()`, called after the window is resized. SDL keeps the top-left anchor across `SDL_SetWindowSize()`, so growing from the 1024x768 bootstrap size to the configured resolution previously pushed the window off the bottom and right of the display. Centering is clamped to `SDL_GetDisplayUsableBounds()` so the window stays clear of the macOS menu bar, and anchors to the bounds' top-left when the window is larger than the usable area, which keeps the title bar reachable.
- Positioning failures are logged rather than swallowed; Wayland rejects programmatic window positioning by design, so this is a warning and not an error.
- Applied to both Generals and Zero Hour.

### Known Remaining Issue

The window-mode pass in `W3DDisplay` corrects both afterwards, so the visible result is right, but the window can briefly flash at the wrong geometry. ### Stop SagePatch.ini From Overriding a User-Authored GameData.ini
- Reported symptom: `MaxCameraHeight` set in a loose `Data/INI/GameData.ini` had no effect in game.
- Root cause was load order in `GameEngine::init()`. The engine loads `Data\INI\Default\GameData` and `Data\INI\GameData` through `initSubsystem()`, then loads the auto-generated `SagePatch.ini` from the user data dir with `INI_LOAD_OVERWRITE`. SagePatch ships a hardcoded `GameData` block (`MaxCameraHeight = 350.0`, `MinCameraHeight = 100.0`, `EnforceMaxCameraHeight = No`, ...), so it silently overwrote whatever the user had authored.
- The loose `Data/INI/GameData.ini` shadows the BIG-archived copy, because `FileSystem::openFile()` resolves local before archive. The archived original is therefore never a factor once a user file exists, so the fix replays that loose file after `SagePatch.ini`, guarded by `TheLocalFileSystem->doesFileExist()`. Installs without a loose `GameData.ini` keep the previous behavior.
- Reloading is safe: under `INI_LOAD_OVERWRITE`, `GlobalData::parseGameDataDefinition()` is plain field assignment with no `newOverride()` push, and the extra load is not fed to `xferCRC`, so the startup light CRC is unchanged.
- Fixed the generated `~5% more terrain` comment, which was passed as a `fprintf` format string and lost the `%` and the following space in every `SagePatch.ini` written to date.
- Updated the generated header comment to document the precedence rule.
- Known trade-off: a loose `GameData.ini` must be a complete copy of the archived file (it shadows, not merges), so the replay makes *every* key in it authoritative — including stock values the user copied without meaning to change. Concretely, stock pins `FramesPerSecondLimit = 30`, so a user file based on the stock copy reverts SagePatch's 60 FPS default unless the user edits that line too. Keys absent from stock (e.g. `TerrainDrawDistanceScale`) keep their SagePatch values.
- Applied to both Generals and Zero Hour.
