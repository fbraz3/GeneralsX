## 02/11/2026

### Fix speedup after in-game save load by re-evaluating logic time scale (#334)
- **Problem**: Loading a savegame from inside a running match caused the simulation to run at 60 FPS (double speed) instead of the intended 30 ticks/sec simulation rate.
- **Root cause (`GameState.cpp`)**:
  - `TheGameEngine->reset()` runs `ScriptEngine::reset()`, which restores the global render FPS limit (e.g. 30 -> 60) but leaves the `TheFramePacer` logic time scale flag untouched.
  - In matches started with the game speed slider at tick rate (30), the time scale flag was disabled (30 < 30 is false).
  - Consequently, after an in-game save load, the simulation ran once per render frame at 60 FPS (double speed). Loading from the main menu was unaffected because `clearGameData()` re-evaluated the flag when leaving the previous game.
- **Fix**:
  - In `GameState::loadGame` (both Zero Hour and Generals base game), re-evaluated `TheFramePacer->enableLogicTimeScale(tickRate < maxFPS)` after the engine reset.
  - Patch provided by [@Moortu](https://github.com/Moortu).
