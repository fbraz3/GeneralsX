# Development Diary - September 2026

## 2026-09-29: Implement SDL3 Windowing and Input Backend for Windows

Enabled the modern SDL3 backend on Windows 64-bit builds (`windows64-deploy` preset), bringing Windows to parity with Linux and macOS while preserving retail VC6 / 32-bit compatibility and avoiding platform assumption traps.

### Motivation & Context
Previously, GeneralsX supported SDL3 + DXVK + OpenAL exclusively on Linux and macOS, while Windows builds remained tethered to legacy Win32/DirectInput stubs or VC6 32-bit. To unify the modern 64-bit architecture across all three operating systems (Linux, macOS, and Windows) without breaking retail online compatibility, we implemented the SDL3 windowing and input backend for Windows.

Upstream TheSuperHackers PR #2639 (by mirelle7) served as an informative reference for MSVC/Windows SDL3 integration patterns, but was adapted to match GeneralsX's cross-platform conventions.

### Architectural Fixes & Anti-Trap Design
Multiple binary platform assumptions (`if APPLE ... else // linux` or `#ifndef _WIN32`) were refactored:
1. **Un-guard SDL3 Device Headers & Sources**:
   - `Include/SDL3GameEngine.h`, `Source/SDL3GameEngine.cpp`
   - `Include/SDL3Device/GameClient/SDL3Mouse.h`, `Source/SDL3Device/GameClient/SDL3Mouse.cpp`
   - `Include/SDL3Device/GameClient/SDL3Keyboard.h`, `Source/SDL3Device/GameClient/SDL3Keyboard.cpp`
   - Gated with `#if defined(SAGE_USE_SDL3)` instead of `#ifndef _WIN32`.
2. **Unified Cursor & Hotspot Logic (`SDL3Mouse.cpp`)**:
   - Eliminated `#ifdef __linux__` restrictions around `has_hotspot` extraction, `first_surface` boundary clamping, and the static color cursor fallback (`SDL_CreateColorCursor`). ANI cursor fallback is now robust and universal across Linux, macOS, and Windows.
3. **Cross-Platform `SDL3Main.cpp`**:
   - Included `<SDL3/SDL_main.h>` for proper `WinMain`/`main` entry point bridging on Windows.
   - On Windows, extracted native Win32 `HWND` from SDL3 properties (`SDL_PROP_WINDOW_WIN32_HWND_POINTER`) so DirectX8 / DXVK can bind to the window.
   - Provided portable environment variable setters and initialized `ApplicationHInstance = GetModuleHandle(nullptr)`.
   - Gated Linux-only Vulkan software ICD filtering behind `#if defined(__linux__)`.
4. **Input Factory Routing (`W3DGameClient.h`)**:
   - Updated `createKeyboard()` and `createMouse()` to instantiate `SDL3Keyboard` and `SDL3Mouse` whenever `SAGE_USE_SDL3` is enabled, falling back to legacy DirectInput/Win32Mouse only when `SAGE_USE_SDL3` is OFF.
5. **Window Visibility & Sizing (`W3DDisplay.cpp`, `dx8wrapper.cpp`)**:
   - Made `SDL_ShowWindow(TheSDL3Window)` trigger across all platforms under `SAGE_USE_SDL3`.
   - Added `SWP_NOSENDCHANGING` to `SetWindowPos` in `dx8wrapper.cpp` to avoid unwanted message reentrancy during mode switches on Windows.
6. **CMake Build System**:
   - Enabled `"SAGE_USE_SDL3": "ON"` for `windows64-deploy` in `CMakePresets.json`.
   - Updated `Core/GameEngineDevice/CMakeLists.txt`, `GeneralsMD/Code/GameEngineDevice/CMakeLists.txt`, `GeneralsMD/Code/Main/CMakeLists.txt`, and base game `Generals/Code/...` to condition on `SAGE_USE_SDL3`.

### Packaging & Self-Contained Runtime DLLs
To ensure the Windows SDL3 bundles are completely self-contained on machines without MSYS2/MinGW:
- Enhanced `scripts/build/windows/deploy-windows-zh.ps1` and `scripts/build/windows/deploy-windows-generals.ps1` to detect and bundle:
  - `SDL3.dll` and `SDL3_image.dll` (compiled natively via FetchContent)
  - `OpenAL32.dll` (OpenAL Soft)
  - `d3d8.dll`, `dxgi.dll`, and `d3d11.dll` (DXVK x64 runtime)
  - MinGW runtime libraries (`libgcc_s_seh-1.dll`, `libstdc++-6.dll`, `libwinpthread-1.dll`)
  - Image/compression libraries (`libpng16-16.dll`, `libzlib1.dll`, `zlib1.dll`)
- Added `Win32OSDisplay.cpp` compilation under `SAGE_USE_SDL3` on Windows to provide `OSDisplaySetBusyState()` without requiring Linux platform stubs.
