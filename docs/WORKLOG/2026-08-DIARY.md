### Fix Multi-Monitor Window Placement and HiDPI Window Sizing
- Fixed the game opening on a secondary monitor at an oversized width on multi-monitor macOS setups.
- Root cause was a unit mismatch: `buildFilteredResolutions()` clamps the resolution list against `SDL3_GetNativeDisplaySize()`, which returns `mode->w * pixel_density` (physical pixels), but `SDL3_ApplyWindowModeForRenderConfig()` passed those values straight to `SDL_SetWindowSize()`, which expects logical points. On a 2x Retina display a 3840x2160 render resolution produced a 7680-physical-pixel-wide window — twice the width of the whole desktop.
- The oversized window then spanned both displays, and because SDL resolves a window's display by its center point, `SDL_GetDisplayForWindow()` reported the adjacent monitor and the window migrated there.
- `SDL3_ApplyWindowModeForRenderConfig()` now derives the pixel-to-point ratio from the window itself (`SDL_GetWindowSizeInPixels` / `SDL_GetWindowSize`) rather than the display's `pixel_density`. The drawable is only scaled when the window carries `SDL_WINDOW_HIGH_PIXEL_DENSITY`, which is set on macOS only, so the ratio collapses to 1.0 on other platforms and non-HiDPI behavior is unchanged.
- `SDL_CreateWindow()` takes no position argument and resolves to `SDL_WINDOWPOS_UNDEFINED`, which SDL maps to display index 0 of its own enumeration order rather than the OS primary display. `SDL3Main.cpp` now pins the initial placement to `SDL_GetPrimaryDisplay()` while the window is still hidden, so there is no visible jump and fullscreen no longer inherits the wrong display.
- Added `SDL3_CenterWindowOnCurrentDisplay()`, called after the window is resized. SDL keeps the top-left anchor across `SDL_SetWindowSize()`, so growing from the 1024x768 bootstrap size to the configured resolution previously pushed the window off the bottom and right of the display. Centering is clamped to `SDL_GetDisplayUsableBounds()` so the window stays clear of the macOS menu bar, and anchors to the bounds' top-left when the window is larger than the usable area, which keeps the title bar reachable.
- Positioning failures are logged rather than swallowed; Wayland rejects programmatic window positioning by design, so this is a warning and not an error.
- Applied to both Generals and Zero Hour.
