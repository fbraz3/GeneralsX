### Fix air unit ground indicator suppression for friendly stealthed aircraft (`fix/stealth-air-unit-ground-indicator`)
- **Problem**:
  - Stealth aircraft owned by the local player (e.g. US Comanche helicopter with the stealth upgrade, or Stealth Fighter) failed to display the tactical ground indicator circle under normal flight conditions.
  - When entering the detection radius of enemy stealth detectors (radar vans, scout drones, base defenses, hero units) or taking fire/destealthing, the indicator would abruptly appear, and then disappear again upon exiting detection.
- **Root Cause**:
  - In commit `45850ccfe` (`feat(graphics): implement tactical air unit ground indicator and selection picking`), stealth look checks were added to `W3DModelDraw::updateAirGroundIndicator()` and `W3DView::pickDrawable()` to suppress indicators on cloaked aircraft.
  - The check used `draw->getStealthLook() != STEALTHLOOK_NONE` and `cand->getStealthLook() != STEALTHLOOK_NONE`.
  - For the friendly controlling player, a stealthed unit is assigned `STEALTHLOOK_VISIBLE_FRIENDLY` (semi-transparent) rather than `STEALTHLOOK_NONE`. Because `STEALTHLOOK_VISIBLE_FRIENDLY != STEALTHLOOK_NONE`, the ground indicator was erroneously suppressed for the local player's own stealth aircraft.
  - Furthermore, `updateAirGroundIndicator()` and `pickDrawable()` already strictly restrict indicators to the local human player's own aircraft (`obj->getControllingPlayer() == ThePlayerList->getLocalPlayer()`), meaning opponents could never see or pick the local player's aircraft indicators anyway.
  - When passing near enemy detectors or taking fire, stealth broke or cleared to `STEALTHLOOK_NONE`, causing the circle to intermittently pop in and out.
- **Fix**:
  - In `Core/GameEngineDevice/Source/W3DDevice/GameClient/Drawable/Draw/W3DModelDraw.cpp` (`W3DModelDraw::updateAirGroundIndicator`), changed the stealth look suppression condition from `draw->getStealthLook() != STEALTHLOOK_NONE` to `draw->getStealthLook() == STEALTHLOOK_INVISIBLE`. Friendly stealthed aircraft (`STEALTHLOOK_VISIBLE_FRIENDLY` / `STEALTHLOOK_VISIBLE_FRIENDLY_DETECTED`) now properly display their tactical ground ring.
  - In `Core/GameEngineDevice/Source/W3DDevice/GameClient/W3DView.cpp` (`W3DView::pickDrawable`), updated the tactical picking filter from `cand->getStealthLook() != STEALTHLOOK_NONE` to `cand->getStealthLook() == STEALTHLOOK_INVISIBLE`, allowing local players to select their own airborne stealthed units via the ground reticle.

### Fix OpenAL audio stream hissing voice sound (#380)
- **Problem**: In campaign maps, voice lines could leave behind a continuous hissing or looping sound artifact.
- **Root cause (`OpenALAudioStream.cpp`)**: When an OpenAL source transitions to `AL_STOPPED`, it has completed playback of all queued buffers, and OpenAL flags them as processed. Calling `play()` on a stopped source rewinds it and replays the old buffers again. Consequently, the final chunk of speech lines looped indefinitely and the stream was never released.
- **Fix**:
  - In `OpenALAudioStream::update()`, explicitly detect `sourceState == AL_STOPPED && num_queued > 0`, unqueue and drop stale played buffers while preserving any freshly queued buffers added immediately prior to `update()`.
  - Restricted the subsequent restart check to `AL_INITIAL` and `AL_PAUSED`.
  - Patch provided by [@Moortu](https://github.com/Moortu) with subsequent frame preservation hardening.

### Fix base Generals crash on startup with German Steam version (#378)
- **Problem**: Base Generals crashed during initialization with German Steam releases (`[INI] ERROR: No files read from directory 'Data\english\Language'`) when `registry.ini` or environment variables lacked explicit language settings.

  - `tryAutoDetectLanguage` only probed for `German.big` and `GermanZH.big`, failing to detect `German2.big` and falling back to default `"english"`.

- **Fix**:

### Fix Microwave Tank heat distortion effect glitching and displaying UI (#384)
- **Problem**: In Zero Hour on Linux and macOS, the Microwave Tank's heat distortion / microwave wave effect glitched continuously, rendering pieces of the user interface (command bar, radar, portraits) across the microwave cone instead of the intended heat shimmer refraction.
- **Root cause (`W3DSmudge.cpp`)**:
  - `W3DSmudgeManager::render()` rendered the refractive heat smudges by copying the background image using `background->Copy(..., backBuffer)`, where `backBuffer` was retrieved via `DX8Wrapper::_Get_DX8_Back_Buffer()`.
  - In retail DirectX 8, 3D scenes were rendered directly to the backbuffer before the UI was drawn. However, in GeneralsX, post-processing (`TheW3DPostProcess->beginScene()`) redirects 3D scene rendering to an offscreen render target (`m_sceneSurface`), only blitting the composited result to the backbuffer after `drawViews()` finishes and before `TheInGameUI->DRAW()`.
  - Furthermore, in Vulkan/DXVK, `GetBackBuffer()` references the swapchain backbuffer, which during 3D world rendering retains the previous frame's rendered content (including the fully drawn UI/HUD).
  - Consequently, `W3DSmudgeManager` copied the previous frame's backbuffer containing the user interface, causing the microwave distortion quads to sample and distort buttons, radar, and fonts instead of the active 3D world.
- **Fix**:
  - In `W3DSmudgeManager::ReAcquireResources()` and `W3DSmudgeManager::render()`, dynamically obtain the active render target via `pDev->GetRenderTarget(&renderTargetD3D)` (falling back to `_Get_DX8_Back_Buffer()` if unavailable).
  - Automatically re-create `m_backgroundTexture` if its dimensions or format differ from the active render target (e.g. resolution change or offscreen surface formats).
  - Copy the background from the active render target rather than the swapchain backbuffer, ensuring that refractive smudges distort the active 3D scene prior to post-processing and UI rendering.
  - Explicitly reset texture stage 0 to `nullptr` upon completing smudge drawing to prevent texture-as-render-target hazards on subsequent render passes.
